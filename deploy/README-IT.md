# استقرار سامانهٔ VLSE — راهنمای واحد IT

سامانهٔ ارزیابی و رتبه‌بندی کیفی تأمین‌کنندگان مواد اولیهٔ دارویی. رابط فارسی و راست‌به‌چپ، داده روی PostgreSQL، اجرا با Docker.

این صفحه همهٔ چیزی است که برای بالا آوردن سامانه لازم دارید. سند مفصل‌تر `IT_DEPLOYMENT_GUIDE.md` است و فقط وقتی لازم می‌شود که بخواهید از مسیر پیش‌فرض خارج شوید.

---

## ۱. آنچه پیش از شروع باید فراهم باشد

| مورد | مقدار لازم |
| :--- | :--- |
| سیستم‌عامل | لینوکس ۶۴بیتی (اوبونتو ۲۲.۰۴ یا بالاتر آزموده شده) |
| Docker | نسخهٔ ۲۴ یا بالاتر، سرویس در حال اجرا |
| Docker Compose | نسخهٔ ۲ (دستور `docker compose`، نه `docker-compose`) |
| رم | حداقل ۴ گیگابایت |
| فضای دیسک | حداقل ۲۰ گیگابایت آزاد |
| دسترسی شبکه هنگام نصب | به رجیستری Docker و npm (بسته‌ها هنگام build دانلود می‌شوند) |
| پورت | یک پورت آزاد روی میزبان؛ پیش‌فرض ۸۰۸۰ |
| نام میزبان | یک نام داخلی مثل `vlse.company.local` در DNS شرکت |
| گواهی TLS | برای reverse proxy جلوی سرویس (بخش ۴) |
| محل پشتیبان | یک مسیر روی فضای پشتیبان شرکت، جدا از دیسک همین سرور |

سامانه به اینترنت **در زمان اجرا** نیازی ندارد؛ فقط هنگام نصب و به‌روزرسانی بسته‌ها دانلود می‌شوند.

---

## ۲. نصب

```bash
unzip VLSE-<نسخه>.zip -d /opt/vlse
cd /opt/vlse
./deploy/install.sh
```

اسکریپت این کارها را می‌کند: پیش‌نیازها را می‌سنجد، فایل `.env` را می‌سازد و رمز پایگاه‌داده و کلید امضای نشست را خودش تصادفی تولید می‌کند، تصویر را build و سرویس‌ها را بالا می‌آورد، تا آماده شدن سامانه صبر می‌کند و در پایان آدرس ورود را چاپ می‌کند.

بار اول بسته به سرعت شبکه چند دقیقه طول می‌کشد. اجرای دوبارهٔ همین دستور بی‌خطر است و مسیر به‌روزرسانی هم هست: `.env` و دادهٔ پایگاه‌داده دست‌نخورده می‌مانند.

**اولین ورود:** نام کاربری `admin` و رمز `123456`. سامانه در همان ورود اول تغییر رمز را اجباری می‌کند. رمز اولیه را در ایمیل یا تیکت ننویسید.

---

## ۳. پس از نصب

```bash
docker compose ps                      # وضعیت سرویس‌ها
docker compose logs -f pharma-app      # لاگ زندهٔ برنامه
curl -s http://127.0.0.1:8080/api/health   # سلامت واقعی (پایگاه‌داده را می‌سنجد)
```

`/api/health` اگر پایگاه‌داده در دسترس نباشد کد ۵۰۳ می‌دهد. همین مسیر را در سامانهٔ مانیتورینگ شرکت بگذارید؛ «کانتینر بالاست» به‌تنهایی معنای «سامانه کار می‌کند» ندارد.

**پشتیبان‌گیری** — دادهٔ سامانه فقط در پایگاه‌داده است و مدارک پیوست SOP هم داخل همان دامپ می‌آیند:

```bash
./deploy/backup.sh /var/backups/vlse
```

یک زمان‌بندی روزانه در crontab بگذارید و پشتیبان را روی فضای پشتیبان شرکت منتقل کنید:

```
0 2 * * *  cd /opt/vlse && ./deploy/backup.sh /var/backups/vlse >> /var/log/vlse-backup.log 2>&1
```

**بازگردانی** (دادهٔ فعلی جایگزین می‌شود و تأیید صریح می‌گیرد):

```bash
./deploy/restore.sh /var/backups/vlse/vlse-20260903-020000.sql.gz
```

## ۴. کارهایی که واحد IT باید انجام دهد

1. **TLS.** سامانه روی HTTP سرو می‌شود و توکن نشست در مرورگر نگهداری می‌شود؛ روی HTTP رمزنگاری‌نشده این توکن در شبکه قابل شنود است. یک reverse proxy (Nginx یا هرچه در شرکت مرسوم است) با گواهی معتبر جلوی پورت سامانه بگذارید و پورت خودِ سامانه را از بیرون نبندید به شبکه.
2. **فایروال.** پورت پایگاه‌داده عمداً روی میزبان منتشر نمی‌شود؛ همان‌طور بماند. دسترسی به پورت برنامه را به شبکهٔ داخلی محدود کنید.
3. **پشتیبان‌گیری زمان‌بندی‌شده** طبق بخش ۳، به‌همراه یک آزمون بازگردانی در محیط آزمایشی.
4. **نگهداری `.env`.** رمز پایگاه‌داده و کلید نشست فقط در همین فایل‌اند. یک نسخهٔ امن از آن نگه دارید؛ با از دست رفتن کلید، همهٔ نشست‌های فعال باطل می‌شوند.
5. **تغییر رمز حساب‌های پیش‌فرض** در همان روز اول.

## ۵. اگر مشکلی پیش آمد

| نشانه | علت محتمل و اقدام |
| :--- | :--- |
| نصب روی مرحلهٔ build متوقف می‌شود | سرور به رجیستری Docker یا npm دسترسی ندارد. دسترسی شبکه یا پراکسی سازمانی را بررسی کنید. |
| صفحه بالا می‌آید ولی همهٔ فهرست‌ها خطا می‌دهند | پایگاه‌داده در دسترس نیست. `docker compose ps` و `docker compose logs postgres_server`. |
| کانتینر برنامه دائم restart می‌شود | مهاجرت پایگاه‌داده شکست خورده. لاگ کانتینر پیام دقیق را دارد. |
| `.env` ناقص است | compose عمداً بالا نمی‌آید و نام متغیر گمشده را می‌گوید. |
| پورت اشغال است | `APP_PORT` را در `.env` عوض و `./deploy/install.sh` را دوباره اجرا کنید. |

برای هر مشکل، این دو خروجی را برای تیم توسعه بفرستید: `docker compose ps` و `docker compose logs --tail=200 pharma-app`. لطفاً محتوای `.env` را نفرستید.
